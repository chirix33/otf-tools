Generated by `python -m domains.it_ops.validate`. Every number below is recomputed from the files in `runs/itops_*` and the raw trace; nothing is hand-entered. Design decisions and deviations from the draft spec: `docs/domains/it_operations.md`, section "As built".

## Result

**PASS**: 0 problem(s) found.

Checks run on every run folder (all windows, all task log rows, all questions):

1. **Determinism.** `sim.simulate` run twice on each window gives identical logs, task histories and end states, and reproduces exactly the task log, the Events section and the queue at window end printed in the PDF (text extracted from the PDF with pypdfium2). A re-run reproduces the task log exactly.
2. **Independent re-implementation.** `ref_engine` in `validate.py` is a second scheduler written from the front-matter prose (different state layout: a flat list of running tasks, free capacity recomputed from it, the reservation time found by scanning candidate times), fed only with numbers parsed back out of the PDF (the Machines table and the submit rows of the task log). It reproduces every printed task log row and the printed queue at window end; run on from the printed queue at window end it gives the same events after the window as `sim.py`; and it re-derives every gold label (descriptive answers, but-for runs for explanatory, continued runs for predictive, re-runs with the change for counterfactual). So each question is answerable from its document alone.
3. **Invariants** on every printed log: the CPU and memory in use on a machine never exceed its capacity; no task starts on a machine while it is down, and every task running on a machine when it fails stops then; only free-tier tasks are evicted; every finish comes exactly one run time after the task's last start; every task submitted in the window either finishes in it or is listed in the queue at window end, never both; the queue tables agree with the log.
4. **Real inputs.** Every task's printed submit time, priority, CPU and memory request and run time equal its raw trace record (job id and task index are kept in the build provenance), and its job was submitted in the window; every machine's capacity is 1/8 of its real machine's recorded capacity; the failure and return times are the real machine's REMOVE and next ADD times; no other machine has a REMOVE in the window. The trace files match the bucket's SHA256SUM, and a second read of the raw task_events files finds the same number of eligible tasks as `data.py` in every slice (parts 120-121: 29551; parts 240-241: 6517; parts 360-361: 22395; parts 470-471: 23809).
5. **Prompt hygiene.** Every prompt starts with its scope title and the question repeats it; every task, job and machine id mentioned belongs to that scope; times mentioned in non-predictive questions lie in the window; no prompt contains the words 'descriptive', 'explanatory', 'predictive', 'counterfactual', 'simulat', 'gold', 'but-for', 'intervention', 'benchmark'; questions.jsonl carries no type or gold; every MC question has at least one true and one false choice.

**CPU time.** One window's full run (the window plus the continued run to the last finish) takes at most 16 ms of CPU in `sim.py` (mean 2.6 ms) and at most 62 ms in the independent scheduler, far under 20 s. Building and screening all 40 candidate windows takes 0.6 s.
